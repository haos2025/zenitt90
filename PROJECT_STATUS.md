Обновлено после сессии аудита пульта ДУ + редизайна Настроек + находки
системного бага с id мульти-источников (см. новый раздел "Готово" внизу
списка — сессия отмечена явно, не перемешана со старой историей).
Актуальный список направлений — `ROADMAP.md`, история решений —

разделом). Этот файл — навигация между промтами для следующих шагов,

**Как пользоваться**: каждый пункт ниже — отдельная сессия с чистым
контекстом. Промт для пункта — в файле `PROMPT_<NAME>.md`, вставляется в
начале сессии вместе с актуальным зипом проекта и файлами, которые сам
промт просит приложить.

### ✅ Сессия: `PROMPT_SETTINGS_UPGRADE.md` + сквозной аудит пульта ДУ на TV + критический баг мульти-источников

Началось с выполнения `PROMPT_SETTINGS_UPGRADE.md` (редизайн Настроек:
иконка+капс-подпись над карточкой, статус-строки для Источников/Синхронизации,
паритет «Обновить парсеры» на телефоне) — но по ходу тестирования на
реальном TV-пульте вскрылась куда более серьёзная, ранее не замеченная
проблема, и сессия переросла в полный аудит D-pad/фокуса по всему
приложению плюс поиск причины полного отказа воспроизведения.

**Класс бага №1 — фокус-ловушки (Surface/Card с пустым или "съедающим"
onClick вокруг реальных интерактивных элементов):**
- `SourcesScreen.kt` — вся карточка источника была одним
  `Surface(onClick = {})`: фокус вставал на карточку, OK не делал ничего,
  до реального переключателя/кнопки «Обновить»/меню «⋮» фокус в принципе
  не мог провалиться. Источники были **полностью неуправляемы с пульта**.
- `PluginCatalogScreen.kt` — та же ловушка в двух местах (карточка
  обновления плагина; переключатель внутри кликабельной карточки плагина).
- Результат применительно к прошлым багам: кнопка «Обновить» источника
  никогда не была нажимаема с пульта — то есть все прошлые репорты
  "плейлист не обновляется на TV" были именно из-за этого, а не из-за
  логики обновления (она всегда была рабочей).

**Класс бага №2 — decorative-компоненты оказались фокусируемыми на
самом деле:**
- `PlayerController.kt`: `IconGlyphButton` (play/pause, перемотка)
  строился на `Modifier.clickable(...)` — тот **всегда** добавляет
  фокусируемость, вопреки комментарию "не получают фокус напрямую".
  D-pad вниз с видео попадал на play/pause раньше настоящих иконок
  настроек, а Left/Right, не поглощённые им, улетали в глобальный
  обработчик и всегда перематывали — отсюда "работает только плей,
  стрелки только мотают". Исправлено `focusProperties { canFocus = false }`.
- `PlayerScreen.kt`: глобальный `onKeyEvent` безусловно перехватывал
  Center/Left/Right/Back независимо от того, что реально в фокусе.
  Теперь эти клавиши глобальные только пока фокус на самом видео
  (`rootHasFocus`); Back ведёт себя стандартно для TV — сначала
  возвращает фокус на видео, второй раз — выходит.

**Класс бага №3 — оверфлоу подсветки за скруглённый край при фокусе:**
у tv-material3 `Surface` по умолчанию фокус ещё и увеличивает сам
компонент (~10%, "pop"-эффект, рассчитан на постеры с гуттерами) — на
полноширинных строках впритык к рамке (Настройки, Источники, панель
настроек плеера, иконки капсулы) это вылезало за край на реальном
экране. Отключено (`scale = ClickableSurfaceDefaults.scale(focusedScale = 1f)`)
везде, где нашлось: `SettingsScreen.kt` (2 компонента),
`PlaybackMenuOverlay.kt` (3 компонента), `PlayerController.kt` (1).

**Класс бага №4 — клавиатура перехватывает D-pad:** `BasicTextField` в
`AddSourceScreen.kt` показывал клавиатуру сразу по факту получения
фокуса стрелками (не по явному OK) — Down/Up не проходили мимо поля к
кнопке ниже. Исправлено двумя режимами: показ-строка (обычная
фокусируемая строка, клавиатура не показывается) / режим редактирования
(входит по явному клику, клавиатура открывается осознанно).

**Класс бага №5 — скролл не следует за фокусом сквозь вложенный
LazyRow:** `DetailScreen.kt` — актёры/похожие фильмы физически не
фокусировались вовсе (общий с телефоном файл, где фокус не нужен). После
починки фокуса выяснилось: обычный `Modifier.verticalScroll()` не умеет
надёжно докручивать экран к элементу за пределами вложенного
горизонтального `LazyRow`. Первая попытка чинить через
`androidx.tv.foundation.TvLazyColumn` — **сборка упала**: этот компонент
полностью удалён из библиотеки ещё до стабильного релиза 1.0.0.
Официальная замена от Google — обычный `LazyColumn` из Compose Foundation
(в него перенесли ту же логику докрутки под D-pad-фокус) — им и починено
в итоге.

**Главная находка сессии — критический баг мульти-источников,
затрагивавший вообще любое воспроизведение с собственного плейлиста:**
`PlaylistSourceRepository.kt` переписывает id парсера в
`"<UUID источника>_m3u_N"` (чтобы несколько playlist-источников не
пересекались по id) — но **четыре** отдельных места в коде определяли
тип контента как «всё до первой `_` в id», ожидая голый `m3u_N`. UUID
состоит из дефисов, не подчёркиваний — проверка возвращала весь UUID
целиком, не совпадавший ни с одним известным типом, и код либо
проваливался в бэкенд-API с локальным id (закономерный настоящий HTTP 404
от Zenith-бэкенда), либо в пустой список вариантов. Найдено и исправлено
на подстроковую проверку в: `GetPlayableUrlUseCase.kt`,
`MovieRepositoryImpl.getMovieById()` (главный виновник — вызывается
первым при открытии карточки с главной ленты, до всякого редиректа на
сериал; через кнопку «Сериалы» не вызывается вовсе, поэтому тот путь
всегда работал), `HomeUiState.isPlaylistSourced`,
`HomeViewModel.resolvePosterIfNeeded`. Отдельно диагностирована и
исправлена (не баг приложения) поломка группировки серий в тестовом
m3u-файле — заголовки с уникальной подписью после `SxxExx` ломают ключ
группировки, рассчитанный на «всё после вычета SxxExx».

**Прочее в этой же сессии:**
- Улучшена диагностика ошибок воспроизведения (`PlayerViewModel.kt`,
  `SeriesViewModels.kt`) — вместо голого "404"/"Нет потоков" теперь видно
  HTTP-код, `errorCodeName` от Media3, сам movieId и URL, класс исключения
  и место в стеке — расследование велось по присланным скриншотам без
  доступа к logcat.
- «Смотрите также» (`RecommendationsRow.kt`) — клик по карточке раньше
  ничего не делал, теперь ищет совпадение по названию в каталоге и либо
  переходит, либо сообщает, что не нашлось. «Актёры» — переход на
  фильмографию НЕ сделан (нужен новый TMDB-запрос по персоне и новый
  экран — не мелкая правка, отдельная сессия при необходимости).
- Избранное — диалог выбора папки больше не показывается, если папок ещё
  нет (сохраняет сразу без папки), на TV и телефоне.
- Кнопка «Назад» в детальной карточке на TV убрана — дублировала
  системную клавишу и путала фокус.
- Телефон: убрана задвоенная лупа поиска (осталась только в нижней
  панели), починен перенос подписей нижней панели на две строки.
- Тестовый m3u-файл для проверки логики сериалов дважды пересобран:
  archive.org и старый googleapis-бакет оказались ненадёжны с сети
  тестировщика — итоговая версия на `test-videos.co.uk`.

## Требует внимания (не готово)

- ⚠️ **Веб-архив (`ia_`) не воспроизводится** — подтверждено на реальном
  устройстве (`ERROR_CODE_IO_NETWORK_CONNECTION_TIMEOUT`), не HTTP-ошибка,
  а сетевой таймаут при подключении — похоже на блокировку/недоступность
  archive.org именно с сети тестировщика (метаданные/поиск при этом
  работают, значит блокировка не тотальная). Не диагностировано до конца —
  теперь часть более широкой темы, см. пункт 1 в "Следующее, по приоритету"
  ниже и `PROMPT_REGIONAL_ACCESS.md`.
- ❓ Стоит перепроверить весь остальной пульт по той же методичке
  (найденные классы багов №1/№2/№3 могли повториться в ещё не
  проверенных экранах — Избранное, История, Поиск целиком не проходили
  этот аудит в эту сессию, смотрели только Настройки/Источники/Плагины/
  Плеер/Детальную карточку).
