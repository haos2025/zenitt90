  Исправлено, актуальный код переносит контекст между фреймами внутри
  одного чанка.
- ⚠️ **Тройное декодирование одного и того же аудио-чанка в PCM**
  (внутри VAD, внутри оркестратора для нарезки WAV под облако, внутри
  локального Whisper при фолбэке) — известная неэффективность, не
  устранена сознательно (потребовала бы менять уже сданные публичные
  сигнатуры). Кандидат на отдельную оптимизацию после профилирования на
  реальном устройстве.
- ⚠️ **Отступ для рендера AI-реплики поверх видео** (`120.dp` на TV,
  `100.dp` на телефоне, в `PlayerScreen.kt`/`PhonePlayerScreen.kt`) —
  подобран приблизительно, чтобы не перекрывать капсулу плеера; нужна
  калибровка на реальном экране/устройстве.

**Известные грабли Kotlin 2.1.20 (проект не на 2.2) — держать в голове
для будущих сессий по этой и другим фичам:**

- `continue`/`break` внутри инлайн-лямбды (например `getOrElse { ...
  continue }`) — фича "non-local break/continue in inline lambdas"
  доступна только с языковой версии 2.2. На 2.1.20 нужно разворачивать в
  явную проверку `Result.isFailure`/`getOrThrow()` с `continue` прямо в
  теле цикла, не внутри лямбды.
- Аннотации вроде `@UnstableApi` (androidx.media3) нельзя вешать
  напрямую на `val ... by lazy { }` (delegated property) — цель "member
  property with delegate" не входит в список применимых. Нужно
  `@get:UnstableApi`, чтобы аннотация целилась в геттер.

## 19. Региональные ограничения доступа (блокировки/DPI) — не начато

Продолжение открытого вопроса из `NEXT_STEPS.md` ("Archive.org требует
VPN") — расширено по запросу Shadow с одного источника (Archive.org) на
общий случай: любой M3U/Xtream-хост, backend-источник или сам
`zenith-backend` может оказаться заблокирован для части пользователей
(регион — Казахстан/Россия, оба с активной практикой блокировок), и
дело не всегда в DNS.

**Известные факты на сейчас (не домысел, см. `NEXT_STEPS.md`/
`TRACKING_TABLE.md`):**
- Archive.org (`ia_`-контент) у Shadow перестал играть без VPN — когда
  именно это стало так (регрессия) и на чьей стороне блокировка (сеть
  Shadow vs Archive.org режет IP хостинга Render, на котором крутится
  `zenith-backend`) — **не диагностировано до конца**, тест с другой
  сети/VPN не проводился.
- Метаданные/поиск Archive.org при этом работают — блокировка не
  тотальная, похоже на TCP/TLS-уровень (таймаут на конкретных `d1`/`d2`
  узлах), не на 403/451 от самого archive.org.

**Промт для следующей сессии по этой теме** — `PROMPT_REGIONAL_ACCESS.md`
(подготовлен, см. файл). Первая сессия по нему — диагностика и
веб-поиск актуального состояния (техники блокировок и то, что сейчас
реально предлагает РосКомСвобода/сообщество, могло измениться с
обучающих данных модели), план на согласование — не сразу код, тот же
принцип, что и у `PROMPT_EPG.md`.
